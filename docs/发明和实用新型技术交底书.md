四、技术方案的详细阐述

1. 基于抽象语法树与正则表达式结合的双层识别技术
发明点： 创新性地提出AST节点类型过滤与正则表达式内容检测相结合的双层识别机制，实现语法级精确识别与内容级中文检测的有机结合，解决了单一技术手段的局限性。
技术特征：
（1）第一层：AST节点类型过滤
使用Babel、Vue编译器等专业解析器构建AST，通过AST节点类型（StringLiteral、TemplateElement、JSXText、JSXAttribute等）精确过滤出可能的字符串节点，自动排除注释节点、变量声明节点、类型注解节点等非字符串节点，从根本上避免误匹配。
（2）第二层：正则表达式内容检测
在通过AST节点类型过滤的基础上，对节点值使用正则表达式/[\u4e00-\u9fa5]/进行中文字符检测，同时结合图片资源扩展名检测、配置化排除列表等机制，进一步过滤不需要翻译的内容。
（3）智能调试上下文排除机制
通过AST路径分析，自动识别并排除调试上下文（console.log、throw Error、assert等）中的中文字符串，避免将调试信息误识别为翻译目标。具体实现：遍历AST路径，检测父节点是否为console调用、Error构造、throw语句或assert调用，如果是则跳过处理。
（4）DOM字符串智能处理
识别包含HTML标签的字符串（如"<div>欢迎</div>"），自动将普通字符串字面量转换为ES6模板字符串，并将DOM标签部分提取为静态文本，中文部分提取为国际化函数调用，保持代码语义完整性。
创新价值： 通过AST与正则表达式的有机结合，既保证了语法级识别的准确性，又实现了内容级检测的灵活性，解决了现有技术无法同时兼顾准确性和灵活性的技术难题。相比单纯使用AST或正则表达式，本技术方案在识别精度和处理效率上都有显著提升。
2. 智能翻译键生成算法（双模式自适应策略）
发明点： 设计了一种支持两种生成模式的智能翻译键生成算法，可根据项目需求在"语义化键名"和"内容去重"两种模式间切换，解决了翻译键管理复杂、冲突频繁以及重复翻译的问题。
技术特征：
（1）模式一：基于文件路径的语义化键名生成（默认模式）
算法步骤：
a) 提取文件路径，按照配置的层级深度（默认2层）截取路径片段，例如：src/components/UserProfile.vue → components-UserProfile
b) 为每个文件生成唯一UUID标识符，确保同一文件内的不同字符串具有唯一性
c) 按照字符串在文件中出现的顺序生成递增序号
d) 最终键名格式：{路径片段}-{文件UUID}-{序号}，例如：components-UserProfile-a1b2c3-1
优势：不同语境下的相同文本可以有不同的翻译，保持语义准确性。
（2）模式二：基于MD5哈希的内容去重键名生成（可选模式）
算法步骤：
a) 对中文字符串进行trim处理，去除首尾空白
b) 使用MD5哈希算法对处理后的字符串进行哈希计算
c) 将32位十六进制哈希值作为翻译键
d) 相同内容的字符串无论出现在哪个文件，都会生成相同的键名
优势：自动实现翻译去重，避免重复翻译相同内容，减少翻译成本，提高翻译一致性。
（3）键名冲突检测与处理
在生成键名时，系统自动检测是否已存在相同的键名，如果存在且内容不同，则通过序号递增或哈希值后追加标识符的方式确保唯一性。
（4）可配置的生成规则
支持通过配置文件自定义键名生成策略，包括路径层级深度、是否使用MD5模式、键名格式等参数。
创新价值： 通过双模式自适应策略，既满足了需要语义化键名的场景（如不同语境下相同文本需要不同翻译），又满足了需要内容去重的场景（如大型项目中大量重复文案），解决了单一策略无法兼顾不同需求的矛盾。
3. 多框架统一处理机制（动态解析器选择与框架特定适配）
发明点： 设计了一套基于文件扩展名的动态解析器选择机制，结合框架特定的AST处理策略，实现了对Vue、React、TypeScript等多种框架的统一处理，解决了不同框架语法差异导致的处理难题。
技术特征：
（1）动态解析器选择机制
根据文件扩展名自动选择对应的AST解析器：
a) .vue文件 → 使用@vue/compiler-sfc解析Vue单文件组件，分别处理template、script、style三个部分
b) .js/.jsx文件 → 使用@babel/parser解析，启用jsx插件
c) .ts/.tsx文件 → 使用@babel/parser解析，启用typescript和jsx插件
d) 解析器配置包括：errorRecovery（错误恢复）、allowReturnOutsideFunction、allowAwaitOutsideFunction等选项，确保对现代语法的支持
（2）Vue框架特定处理
a) 使用Vue SFC（Single File Component）解析器解析.vue文件，获取descriptor对象
b) 分别处理template部分（使用Vue模板AST）和script部分（使用Babel AST）
c) 对于template部分，遍历AST节点，识别文本节点、属性节点等，生成Vue特定的国际化调用（如$t('key')）
d) 对于script部分，复用JavaScript处理逻辑，但禁用自动导入（由template统一处理）
e) 支持Vue 3的script setup语法
（3）React/JSX框架特定处理

b) 对于JSXText，替换为JSX表达式容器包裹的国际化函数调用：{t('key')}

c) 不同框架使用不同的导入路径和函数名（如Vue使用$t，React使用t）

创新价值： 通过动态解析器选择与框架特定适配的结合，实现了"一套代码，多框架支持"的目标，新框架的适配时间从数周缩短至数小时，大幅提高了工具的适用性和扩展性。

七、术语解释
请对本交底书中提及的关键术语、技术缩略语进行解释说明，如果有英文缩写，必须给出英文全称和中文注释，若有英文单词，必须给出中文注释或者解释。
1. 抽象语法树（Abstract Syntax Tree，AST）
定义： 源代码的树状表示形式，每个节点表示源代码中的一个结构。
在本发明中的应用： 用于解析和理解代码结构，准确识别需要翻译的字符串字面量。
示例：
// 源代码
const message = "欢迎使用系统";

// 对应的AST结构
{
  type: "VariableDeclaration",
  declarations: [{
    type: "VariableDeclarator",
    id: { type: "Identifier", name: "message" },
    init: { type: "StringLiteral", value: "欢迎使用系统" }
  }]
}
2. 国际化（Internationalization，i18n）
定义： 使软件能够适应不同语言和地区的过程，其中"i18n"是"internationalization"的缩写（i和n之间有18个字母）。
在本发明中的应用： 将代码中的中文字符串替换为多语言支持的结构。
3. 翻译键（Translation Key）
定义： 用于标识翻译内容的唯一标识符，通常是一个字符串。
在本发明中的应用： 为每个中文字符串生成唯一的翻译键，用于在多语言文件中查找对应的翻译。
示例：
// 翻译键
"user.login.welcome"

// 对应的翻译内容
{
  "zh-CN": "欢迎登录",
  "en-US": "Welcome to login"
}
4. 正则表达式（Regular Expression）
定义： 用于匹配字符串中字符组合的模式。
在本发明中的应用： 用于检测字符串中是否包含中文字符。
示例：
const chinesePattern = /[\u4e00-\u9fa5]+/; // 匹配中文字符的正则表达式
5. Babel解析器
定义： JavaScript编译器，用于将现代JavaScript代码转换为向后兼容的版本。
在本发明中的应用： 用于解析JavaScript和TypeScript代码，生成AST。
6. Vue编译器
定义： Vue.js框架的编译器，用于解析Vue单文件组件。
在本发明中的应用： 用于解析Vue文件的template、script和style部分。
7. JSX语法
定义： JavaScript XML的缩写，是React中用于描述用户界面的语法扩展。
在本发明中的应用： 需要特殊处理的语法结构，用于React组件中的文本内容。
8. IDE（Integrated Development Environment）
定义： 集成开发环境，提供代码编辑、调试、编译等功能的软件。
在本发明中的应用： VS Code等IDE，用于集成国际化处理功能。
9. 扩展（Extension）
